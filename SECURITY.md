# Reporting problems

The checker reads JSON data. It does not execute submitted Prolog, fetch sources,
call models, or write decisions into an external system. Run it with ordinary
local permissions. Do not treat a passing record as certification of an action.

Report reproducible parser, input-handling or rule-bypass problems with a minimal
fictional case. Redact secrets and participant identities. The intended project
contact for non-sensitive reproducible problems is the
[repository issue tracker](https://github.com/maciejjankowski/zizkian/issues).
The public project does not define a private disclosure channel or a response-time
commitment. Do not post private evidence or exploit details involving someone
else's records.

Known semantic limits include mislabelled evidence, fabricated sources, weak
tests and misreported consent. These are documented limits rather than claims
that every well-formed input is sound. Very large inputs are not a tested service
workload; this is a local experimental tool, not a hosted multi-tenant service.
